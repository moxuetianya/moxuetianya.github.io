微信 Linux 版启动失败：apt 装了依赖却没装全

八月 02, 2026 [debug, linux] #wechat #deb #apt #ldd

背景

Ubuntu 上通过 apt install ~/下载/WeChatLinux_x86_64.deb 安装了微信 Linux 版，但从 GNOME 应用菜单点击图标后没有任何反应，窗口不出现，进程直接退出。

定位：直接运行拿到报错

从桌面点图标失败只能看到"无反应"，先绕过桌面环境，直接跑二进制拿错误信息：

$ /usr/bin/wechat
/usr/bin/wechat: error while loading shared libraries:
libxcb-icccm.so.4: cannot open shared object file: No such file or directory

原因清楚了：缺少动态库 libxcb-icccm.so.4，对应 Debian/Ubuntu 包 libxcb-icccm4。

补完一个又缺一个

$ sudo apt-get install -y libxcb-icccm4
$ /usr/bin/wechat
libxcb-image.so.0: cannot open shared object file: No such file or directory

再装 libxcb-image0，又报 libxcb-render-util.so.0……典型的"补完一个又缺一个"。与其一个个试，不如一次性查出所有缺失：

$ ldd /opt/wechat/wechat | grep "not found"
	libxcb-image.so.0 => not found
	libxcb-render-util.so.0 => not found
	libxcb-keysyms.so.1 => not found

ldd 直接列出全部缺失，不用再来回跑二进制。一次装齐：

$ sudo apt-get install -y libxcb-image0 libxcb-render-util0 libxcb-keysyms1
$ ldd /opt/wechat/wechat | grep "not found"   # 空，依赖齐全

从 GNOME 启动微信，正常。

根因：deb 元数据声明的依赖不全

问题来了：明明用 apt install 装的，为什么依赖没有自动装上？

查看 deb 包的元数据就明白了：

$ dpkg-deb -f ~/下载/WeChatLinux_x86_64.deb Package Version Architecture
wechat
4.1.1.8
amd64

$ dpkg-deb -f ~/下载/WeChatLinux_x86_64.deb Depends
fonts-noto-cjk | google-noto-cjk-fonts

腾讯的 deb 包只声明了一个字体依赖，而二进制实际运行需要的 4 个库：

缺失库对应包
libxcb-icccm.so.4libxcb-icccm4
libxcb-image.so.0libxcb-image0
libxcb-render-util.so.0libxcb-render-util0
libxcb-keysyms.so.1libxcb-keysyms1

全部没有写入 Depends 字段。apt 只能根据包元数据解析依赖，元数据里没声明的它无从知道，自然也不会安装——等到运行时动态链接器报错才暴露。

顺带说明：apt install ./xxx.deb 与 dpkg -i 的区别在于前者会自动解析并安装已声明的依赖；但本案中缺失的库根本未声明，用哪个都装不上，只能手动补。

总结

  1. 桌面图标启动失败先跑二进制：绕过桌面环境的静默失败，拿到真实报错
  2. 缺库报错用 ldd <binary> | grep "not found" 一次性查全，不要补完一个再试一次
  3. apt 装了依赖"没生效"时，先查 deb 元数据：dpkg-deb -f xxx.deb Depends，确认是打包疏漏还是安装方式问题。微信 deb 的 Depends 只声明了字体，4 个 libxcb 运行库全部缺失，这是腾讯打包的锅，不是 apt 的错
