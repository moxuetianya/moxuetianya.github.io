服务器管理口（BMC/iBMC）排查与配置指南：NPU 与 GPU 服务器实测

八月 13, 2026 更新: 八月 14, 2026 [linux] #bmc #ipmi #hardware #npu

背景

家里/机房两台服务器需要确认管理口（BMC）是否开启、如何查看与配置，供后续远程带外管理（KVM、开关机、看硬件状态）参考：

  • NPU 服务器（ssh npu）：华为 Atlas，aarch64（Kunpeng），BMC 芯片为华为 iBMC（Hi171x）
  • GPU 服务器（ssh gpu）：x86_64，BMC 为 AMI（Supermicro 系）

第一步：确认服务器有没有 BMC

登录服务器后，几个命令快速判断管理芯片是否存在：

ls /dev/ipmi*                      # 有 /dev/ipmi0 说明 IPMI/BMC 设备在位
lspci | grep -iE 'bmc|ipmi|ast|management'
# Atlas:  Huawei Hi171x Series [iBMC Intelligent Management system chip w/VGA support]
# x86:    ASPEED Graphics Family / AST1150
dmesg | grep -iE 'ipmi|bmc'        # IPMI message handler / ipmi_si probing

两台服务器都有 /dev/ipmi0，BMC 硬件在位。

第二步：安装 ipmitool 并查看管理口状态

# Ubuntu: 需要 root（/dev/ipmi0 默认 root 权限）
sudo apt-get install -y ipmitool
sudo ipmitool lan print 1          # 查看管理口 LAN 配置
sudo ipmitool mc info              # 查看 BMC 固件信息

NPU 服务器（Atlas iBMC）实测结果

IP Address Source       : DHCP Address
IP Address              : 0.0.0.0          ← 未启用/未接入网络
MAC Address             : b0:4f:a6:0d:2f:f1
Default Gateway IP      : 0.0.0.0
Firmware Revision       : 3.03
IPMI Version            : 2.0
Manufacturer ID         : 2011             ← Huawei

结论：管理口硬件在位但未开启（DHCP 且 IP 为 0.0.0.0），需要配置静态 IP 并接网线到专用 MGMT 口。

GPU 服务器（AMI BMC）实测结果

IP Address Source       : Static Address
IP Address              : 10.10.10.10      ← 已配置（可能是出厂默认）
Subnet Mask             : 255.255.255.0
MAC Address             : 8c:1a:f3:11:59:a1
Default Gateway IP      : 10.10.10.1
SNMP Community String   : AMI
Firmware Revision       : 1.12

结论：管理口已开启，静态 IP 10.10.10.10/24，网关 10.10.10.1。注意该网段与业务网（192.168.6.0/22）隔离，直接访问需要路由或直连管理口。

第三步：配置管理口 IP

用 ipmitool lan set 从操作系统内直接配置（无需进 BIOS）。实测完整命令序列（NPU 服务器上验证通过）：

# 1. 改为静态 IP
sudo ipmitool lan set 1 ipsrc static
# 2. 设置管理口 IP 与子网掩码
sudo ipmitool lan set 1 ipaddr 192.168.6.10
sudo ipmitool lan set 1 netmask 255.255.252.0
# 3. 设置网关 —— 注意：defgw 必须带 ipaddr 子命令！
#    直接写 `sudo ipmitool lan set 1 defgw 192.168.6.1` 会报错：
#    "LAN set default gateway Commands: ipaddr, macaddr"
sudo ipmitool lan set 1 defgw ipaddr 192.168.6.1

实测踩坑：defgw 不是直接给 IP，而是子命令集合，必须写成 defgw ipaddr <IP>（或 defgw macaddr <MAC>），否则命令报错。

改完验证（配置写入 ≠ 链路通了）：

sudo ipmitool lan print 1 | grep -iE 'IP Address|gateway'   # 确认配置已生效
ping -c 2 192.168.6.10                                       # 通 = 链路+网络正常
ip neigh | grep 192.168.6.10                                 # 有 lladdr = ARP 解析成功

NPU 实测结果：配置成功写入（IP Address Source: Static、192.168.6.10/22、网关 192.168.6.1），但 ping 不通、ARP INCOMPLETE —— 说明管理口网线没插/没接到交换机，物理链路未通。配置 IP 后必须插网线才生效，这是配置正确但连不上的最常见原因。

注意事项：

  • 管理口是专用 MGMT 口，不是业务网口（业务口在 Atlas 上是 I350 四口，管理口是独立小口，MAC b0:4f:a6:0d:2f:f1）
  • 改完后需把网线插到管理口，并在能路由到该网段的地方访问
  • Atlas 出厂默认管理 IP 通常是 192.168.1.2，AMI 系默认常用 10.10.10.10（GPU 本机就是）
  • 管理口建议与业务网分开 VLAN，或按需调整到可达网段
  • GPU 服务器（AMI BMC）按同样命令即可改（改前记下当前值：10.10.10.10/24，网关 10.10.10.1，改完用 lan print 1 确认）

第四步：使用管理口

BMC 开启且 IP 可达后，三种方式：

1. Web 界面（推荐）

https://<管理IP>     # iBMC: 默认用户 Administrator；AMI: 常见 ADMIN/ADMIN

可远程 KVM 桌面、开关机、看硬件健康（传感器/SEL 日志）。

2. SSH 进 BMC

ssh Administrator@<管理IP>     # iBMC 命令行

3. IPMI 命令（带外电源管理）

ipmitool -I lanplus -H <管理IP> -U <用户> -P <密码> power status   # 看电源状态
ipmitool -I lanplus -H <管理IP> -U <用户> -P <密码> power on       # 开机
ipmitool -I lanplus -H <管理IP> -U <用户> -P <密码> sel list        # 看系统事件日志

补充：IPMI 通道（channel）详解

ipmitool lan set 1 里的 1 是 channel 编号。BMC 内部有多个通道（编号 0~15），每个通道是不同通信介质，对应不同用途。通道是 BMC 内部的通信媒介，不是物理网口，多数通道由 BMC 后台自动工作，无需用户操作。

查看通道

sudo ipmitool channel info <n>     # 看单个通道（n = 0~15）
# 循环列出所有有效通道：
for c in $(seq 0 15); do echo -n "ch$c: "; sudo ipmitool channel info $c 2>&1 | grep 'Channel Medium Type'; done

通道类型与用途

Channel介质用途用户操作
1802.3 LAN专用管理口（Dedicated BMC 网口，lan set 1 操作的就是它）lan print 1 / lan set 1
2Serial/ModemSOL：串口重定向，远程看 BIOS/POST/内核启动日志，系统崩了也能进 BIOSipmitool sol activate
4SMBus v2.0BMC ↔ 主板传感器/EEPROM 通信总线无（自动）
5/14/15System InterfaceKCS 系统接口：OS 内 /dev/ipmi0 与 BMC 通信的通道（本地跑 ipmitool 就是它）本地 ipmitool sdr list 等
6/10IPMB (I2C)BMC 内部管理总线：连接电源、背板、风扇板等管理芯片无（自动）
7/8802.3 LAN共享 LAN（Share LAN）或同口别名，见下lan print 7/8

三个 LAN 通道 ≠ 三个物理网口

NPU 服务器（华为 iBMC）实测：只有 ch1 一个 LAN 通道（lan print 2 报 "Invalid channel: 2"），其余是 IPMB/System Interface。

GPU 服务器（AMI BMC）实测：有 ch1/ch7/ch8 三个 LAN 通道。通过对比 MAC 判断物理口归属：

ch1: 8c:1a:f3:11:59:a1   ← 专用管理口
ch7: 8c:1a:f3:11:59:a2   ← MAC 独立，OS 里无对应网口（未引出机箱的口）
ch8: 8c:1a:f3:11:59:a1   ← MAC 与 ch1 相同 = ch1 的别名/同口，忽略
eno1: 8c:1a:f3:11:59:a3  ← 业务口
eno2: 8c:1a:f3:11:59:a4  ← 业务口

结论：三个 LAN 通道实际只有 1 个物理管理口（a1）。真正的管理口 = ch1。MAC 编号连续（a1~a4）说明同一网卡控制器生产。判断方法：lan print 7/8 的 MAC 与 ip link 里业务口的 MAC 对比——相同才是共享 LAN（复用业务网口），独立 MAC 则是独立物理口或固件别名。

各通道的实际用法

SOL（ch2）— 远程串口控制台：

ipmitool -I lanplus -H <管理IP> -U <用户> -P <密码> sol activate

前提：BMC Web 界面启用 SOL，内核启动参数带 console=ttyS0（AMI 默认一般已配好）。

KCS（ch5/14/15）— 本地 ipmitool 的默认通道（不带 -I lanplus -H 时自动走它）：

sudo ipmitool sdr list            # 全部传感器（温度/风扇/电源电压）
sudo ipmitool sensor list         # 同上，更详细
sudo ipmitool sel list            # 系统事件日志（上次宕机原因）
sudo ipmitool fru print           # 硬件 FRU 信息（型号/序列号）

NPU 实测输出（华为 5104-00715）：Inlet Temp 23°C / CPU1 Core 50°C / Power 390W。

共享 LAN（ch7/8）：若要在 BMC Web 界面 → Network 开启 "Share LAN"，BMC 复用业务网口，无需插管理口网线。

补充：没登录服务器时如何访问管理口（带外访问）

管理口是带外的——不依赖服务器 OS，只要管理口本身联网（网线 + IP 可达）就能直接访问。OS 进不去、系统没装、崩溃时都能用。

1. 知道 IP：直接访问

https://<管理IP>     # 浏览器
ssh <用户>@<管理IP>  # SSH 进 BMC

2. 不知道 IP 时如何找到

  • 出厂默认 IP（电脑配同网段静态 IP，网线直连管理口）：
    • 华为 iBMC：192.168.1.2/24
    • AMI/Supermicro：多数出厂 DHCP（接公司网络后去 DHCP 服务器按 MAC 查），部分型号固定 10.10.10.10
  • 扫描发现（管理口已接交换机）：
    arp -a                    # 邻居表里找新出现的 MAC
nmap -sn 192.168.6.0/24   # 网段扫描
  • MAC 对照：管理口 MAC 印在机箱贴纸/手册上，arp -a 匹配到即是

3. 默认账号密码

厂商默认账号
华为 iBMCAdministrator / Admin@9000
AMI (Supermicro)ADMIN / ADMIN

一般印在机箱侧面标签。忘记/改过密码的恢复方式：

  • iBMC：机箱上恢复默认跳线/按钮，或 USB 串口线接 M3 micro-USB 口进 CLI 恢复
  • AMI：进 BIOS → BMC 设置 → 恢复出厂

4. 网络彻底不通时

USB 串口线直连管理串口（华为 M3 micro-USB 口）进 iBMC CLI，查 IP / 恢复默认 / 直接命令行操作。

补充：修改/重置管理口密码

用 ipmitool 修改密码

先查用户 ID（NPU 实测 Administrator 是 ID 2）：

sudo ipmitool user list 1                    # 查看用户列表与 ID

本地修改（登录服务器后，零停机，不需要旧密码）：

sudo ipmitool user set password 2 <新密码>

带外修改（从任意机器走管理口网络，需要旧密码——先要认证）：

ipmitool -I lanplus -H <管理IP> -U <用户> -P <旧密码> user set password 2 <新密码>

为什么本地不需要旧密码？ 两种通道的信任模型不同：

方式通道需要旧密码？原理
登录服务器后本地 ipmitoolKCS 系统接口（/dev/ipmi0）不需要BMC 把系统接口视为物理可信路径，OS root 权限即认证本身
通过管理口网络（lanplus）LAN 通道需要网络访问必须先通过用户名+密码认证

本质：本地 = 物理可信域，带外 = 网络身份认证域。这也是安全设计——管理员忘记 BMC 密码时仍能从 OS 内重置，不会彻底锁死。

其他用户管理命令：

sudo ipmitool user enable 2                  # 启用用户
sudo ipmitool user disable 2                 # 禁用用户

注意：新密码不能与当前相同；华为 iBMC 密码要求 8~20 位且含大写/小写/数字/特殊字符中至少三类。

忘记密码时如何 reset（不需要停机）

情况方法停机要求
能登录 OS本地 ipmitool user set password（见上）零停机
不能登录 OS机箱恢复按钮/跳线 → 恢复出厂（含默认密码）需断电物理操作
不能登录 OS华为 M3 串口进 iBMC CLI不需停机，但 CLI 用同一套账号，忘光则无效
不能登录 OS（AMI）BIOS → BMC 设置 → 恢复出厂需重启系统进 BIOS

关键原理：BMC 是独立小系统，重启/复位 BMC 不影响 OS 运行（仅 KVM/SOL 短暂断几秒）。所谓"停机"只来自物理操作（跳线/按钮）和进 BIOS 这两条路径，改密码/恢复出厂本身不动业务。

补充：通过管理口重装系统（远程挂载 ISO + KVM）

管理口（BMC）可以完整重装系统：远程挂载 ISO 当虚拟光驱 + KVM 远程控制台看到屏幕并操作。

什么是 KVM？

KVM = Keyboard + Video + Mouse（键盘、显示、鼠标）。不是多键鼠，而是"虚拟一套键鼠 + 屏幕"：

  • Video：服务器的显卡输出（屏幕画面）通过管理口实时传到浏览器显示
  • Keyboard/Mouse：浏览器里的鼠标键盘输入回传给服务器
你的浏览器 ←网络(管理口)→ 服务器 BMC → 虚拟显卡+虚拟键鼠 → 服务器主机
（你看到的画面）                        （KVM 芯片捕获/注入）

特点：

  • KVM 是带外的：系统没装、卡在 BIOS、系统崩溃时都能看到屏幕并操作
  • Web 界面能看到 BIOS：开机自检（POST）、BIOS 设置、GRUB、安装界面全过程可见可操作
  • 一台服务器同一时间只能被一个 KVM 会话控制（单控），不同于 IPMI 命令可多会话
  • NPU 的 iBMC 和 GPU 的 AMI 都支持，Web 界面找"远程控制台 / Remote Console / iKVM"入口

重装系统完整流程

  1. 浏览器访问 https://<管理IP>（iBMC 默认用户 Administrator；AMI 常见 ADMIN/ADMIN）
  2. 打开远程控制台（KVM）
  3. Virtual Media / 虚拟光驱 → 挂载 ISO 镜像（上传本地文件或填 HTTP 下载链接）
  4. 设置下次从虚拟光驱启动（BMC 里设 boot order，或用命令）：
    ipmitool -I lanplus -H <管理IP> -U <用户> -P <密码> chassis bootdev cdrom   # 下次从虚拟光驱启动
ipmitool -I lanplus -H <管理IP> -U <用户> -P <密码> chassis power reset      # 重启
  5. KVM 窗口里即可看到安装界面（BIOS → 安装器全流程），正常安装

注意事项：

  • 装完把启动顺序改回硬盘：chassis bootdev disk
  • 替代方案：PXE 网络启动（chassis bootdev pxe + 同网段 PXE 服务器，数据流走业务网口）
  • SOL 串口只能文本安装（Ubuntu Server 文本安装器），不支持图形界面
  • ISO 挂载的数据流走管理口网线，一般 1GbE，速度可接受
  • 挂载 ISO 后需在 BIOS 里允许虚拟光驱启动

总结

  • 判断 BMC 是否在位：/dev/ipmi0 + lspci + dmesg
  • 查看管理口是否开启：sudo ipmitool lan print 1 —— IP 为 0.0.0.0（DHCP 未拿到）说明未开启，有具体 IP 说明已开启
  • 配置：ipmitool lan set 1 系列命令，静态 IP/掩码/网关
  • 使用：Web（https://<IP>）、SSH、IPMI over LAN
  • 现状记录：NPU（Atlas iBMC）管理口未开启待配置；GPU（AMI）已开启 10.10.10.10/24
