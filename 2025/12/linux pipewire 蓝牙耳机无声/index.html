linux pipewire 蓝牙耳机无声

十二月 22, 2025 更新: 九月 02, 2026 #pipewire #bluetooth

解决方案

修改bluetooth策略

sudo vim /etc/bluetooth/main.conf
[Policy]
AutoEnable=true
JustWorksRepairing=always
AutoConnect=true
#  end config

# 删除后重新配置
bluetoothctl devices
sudo cat /var/lib/bluetooth/88:D8:2E:2B:20:09/41:AA:00:56:F4:FC/info
bluetoothctl remove 41:AA:00:56:F4:FC

sudo systemctl restart bluetooth

排查记录

只有声音没有麦克风？

  • 通常是因为蓝牙协议在“高音质播放”和“双向通话”之间切换失败，或者系统默认选择了错误的音频配置文件（Profile）
  • 蓝牙耳机通常有两种工作模式：
    • A2DP (High Fidelity Playback)：高音质立体声输出，麦克风不可用。
    • HSP/HFP (Headset Head Unit)：低音质单声道/立体声，麦克风可用（用于通话）。

解决方案

  • 直接在系统配置中切换, 设置 (Settings) -> 声音 (Sound),将配置从 High Fidelity Playback (A2DP Sink) 改为 Headset Head Unit (HSP/HFP) 或 Handsfree Head Unit (HFP)
  • 系统自带设置找不到切换profile选项，使用pavucontrol (PulseAudio Volume Control) 是最有效的工具。即使你使用的是 PipeWire，它也兼容
    • 最右侧的 配置 (Configuration) 选项卡
    • 配置文件 (Profile) 从 High Fidelity Playback (A2DP Sink) 修改为 Headset Head Unit (HSP/HFP)

案例（2026-09）：显示"已连接"却从扬声器出声 —— gdm 登录界面抢占蓝牙音频注册权

现象

GNOME 蓝牙面板显示耳机已连接，但声音一直从扬声器出。wpctl status / pactl list cards short 里根本没有蓝牙声卡（只有 built-in 声卡）。

关键认知：蓝牙"已连接" ≠ 音频链路已建立。 耳机和电脑之间可能只挂着 LE（低功耗）链路——GATT 电量能正常读（bluetoothctl info 里有 Battery Percentage），GNOME 就显示"已连接"，但 A2DP 音频链路从未建立。本案例中连接名带 _LE 后缀（xxx_LE），经典链路连上后名字变成 xxx，可据此识别当前挂的是哪条链路。

排查链

  1. bluetoothctl info <MAC> 显示 Connected: yes，但 bluetoothd 日志全是失败：
    a2dp-sink profile connect failed for XX:XX:XX:XX:XX:XX: Device or resource busy
avdtp.c:cancel_request() Discover: Connection timed out (110)
    跨越数天多次尝试（8/27、8/28、9/2）全部同样失败。本案例其实叠了两个独立问题：
    • 耳机同时连了手机：多设备耳机通常把经典 A2DP 链路让给"优先/最后连接"的设备。手机蓝牙一关，重连立刻成功。这类耳机行为，不是电脑故障。
    • 常驻主因：gdm 抢占注册（见下）。
  2. 手机断开、经典链路通了之后（BlueZ 出现 Endpoint sep1/sep2 和 Transport .../fdN），PipeWire 里依然没有蓝牙声卡；wireplumber 日志：
    RegisterProfile() failed: org.bluez.Error.NotPermitted
Properties changed in unknown transport '/org/bluez/hci0/dev_XX/dev_AA_BB_CC_DD_EE_FF/sep1/fd3'.
Multiple sound server instances (PipeWire/Pulseaudio/bluez-alsa) are probably trying to use Bluetooth audio at the same time ...

根因：GDM 登录界面抢占了 profile 注册权

gdm 是干什么的？为什么它会有音频服务？

GDM（GNOME Display Manager）是 Ubuntu 的显示管理器，负责开机后的登录界面、多用户切换界面。登录界面（greeter）运行在独立系统用户 gdm 下，它本身也是一整套 GNOME 会话（gnome-shell + 自己的 systemd user 实例），所以也有自己的 pipewire/wireplumber——登录界面也要能播放提示音、辅助功能音效。

这套 gdm 音频服务由 socket 激活触发（比如登录界面某次音频请求），启动后常驻不退出，而且它注册的蓝牙 profile 不会因为用户会话存在而让位。本机实例：8/12 16:32 greeter 音频栈启动并注册成功（ps 可见 gdm 用户的 wireplumber），此后用户会话的 wireplumber 无论怎么重启都注册失败。蓝牙声卡从那天起就没了：日志显示 8/27 起每次连接尝试都失败，而"以前成功过"正是 8/12 16:32 之前。（用户会话 8/12 上午先启动，注册权却被下午的 greeter 拿走——注册只有"成功/失败"两态，谁先注册成功谁持有，另一方被拒；历史细节随日志轮转已不可考。）

"profile 注册权"是什么？

蓝牙音频协议栈分两层：

  • BlueZ（bluetoothd）：内核之上的蓝牙核心，管理链路与信令（ACL、AVDTP、SDP 等）。
  • 声音服务器（PipeWire/wireplumber，或旧时代的 PulseAudio/bluez-alsa）：真正的音频编解码与数据流收发在用户态完成。

两层通过 D-Bus 协作。声音服务器启动时向 BlueZ 的 ProfileManager1 接口调用 RegisterProfile(uuid, ...) 登记自己支持的蓝牙音频 profile（A2DP 高音质播放、HFP/HSP 通话等），相当于宣告："这类音频服务由我提供，设备连上来就找我。"（A2DP/HFP/HSP 对应 UUID 都在其中，见 libspa-bluez5。）

BlueZ 对每个 profile UUID 全系统只允许一个注册者——这是合理设计：一套系统本该只有一个声音服务器。后来者注册同一 UUID 会被拒：

org.bluez.Error.NotPermitted

谁注册成功，谁就持有"注册权"直到其会话退出；之后任何新注册（新用户登录、重启 wireplumber、另一用户的会话）都被拒绝。wireplumber 注册被拒后认为"蓝牙音频已被别的服务器管理"，整个 bluez5 模块放弃工作，于是该会话的 PipeWire 里永远不会出现蓝牙声卡，声音只能从扬声器出——与现象完全吻合。

修复（实测有效）

# 1. 停掉 gdm（登录界面）的音频栈，释放注册权（会弹 sudo 确认框）
sudo -u gdm env XDG_RUNTIME_DIR=/run/user/$(id -u gdm) systemctl --user stop wireplumber pipewire pipewire-pulse

# 2. 重启自己的 wireplumber 重新注册，并重连耳机
systemctl --user restart wireplumber
bluetoothctl disconnect <MAC>
bluetoothctl connect <MAC>

# 3. 确认蓝牙 sink 出现并设为默认、解除静音
wpctl status                        # 应出现 [bluez5] 设备与耳机 sink
wpctl set-default <sink-id>
wpctl set-mute <sink-id> 0
wpctl set-volume <sink-id> 0.6

防复发：mask gdm 的音频 unit（登录界面没有音频需求，代价只是登录界面不出声）。gdm 的 home 是 /var/lib/gdm3，把 user unit 软链到 /dev/null 即 mask，重启/锁屏后不会再自动启动：

sudo mkdir -p /var/lib/gdm3/.config/systemd/user
sudo bash -c 'cd /var/lib/gdm3/.config/systemd/user && \
  for u in wireplumber.service pipewire.service pipewire-pulse.service \
           pipewire.socket pipewire-pulse.socket; do ln -sf /dev/null "$u"; done'

自查清单（声音留在扬声器 / 蓝牙无声时）

  1. wpctl status 有没有 [bluez5] 设备？没有 → 音频服务器层面就没拿到蓝牙。
  2. journalctl --user -u wireplumber | grep RegisterProfile：出现 NotPermitted → 注册权被别的会话抢了。
  3. ps -eo user,args | grep wireplumber：出现 gdm 或其他已登录用户的 wireplumber → 就是它抢的（多用户/登录界面都会各起一套音频栈）。
  4. 若注册正常但 bluetoothctl 反复 Discover: Connection timed out / Host is down：多为耳机经典链路被手机等其他设备占用，从耳机侧断开其它设备即可。
