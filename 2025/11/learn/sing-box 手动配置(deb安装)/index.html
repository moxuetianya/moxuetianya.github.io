sing-box 手动配置

十一月 12, 2025 更新: 八月 21, 2026 #anytls #reality #sing-box #hysteria2 #shadowsocks #httpupgrade

安装sing-box（deb 仓库 / install.sh / GitHub 下载）

官方 deb 仓库安装

sudo mkdir -p /etc/apt/keyrings &&
   sudo curl -fsSL https://sing-box.app/gpg.key -o /etc/apt/keyrings/sagernet.asc &&
   sudo chmod a+r /etc/apt/keyrings/sagernet.asc &&
   echo '
Types: deb
URIs: https://deb.sagernet.org/
Suites: *
Components: *
Enabled: yes
Signed-By: /etc/apt/keyrings/sagernet.asc
' | sudo tee /etc/apt/sources.list.d/sagernet.sources &&
   sudo apt-get update &&
   sudo apt-get install sing-box # or sing-box-beta

官方 install.sh 脚本

curl -fsSL https://sing-box.app/install.sh | sh
curl -fsSL https://sing-box.app/install.sh | sh -s -- --version 1.12.12
sudo mkdir -p /var/lib/sing-box/ /etc/sing-box/
sudo systemctl start sing-box

GitHub 下载安装（指定版本，可自定义目录）

# 服务端：安装到 /opt/sing-box/
sudo mkdir -p /opt/sing-box/conf
wget https://github.com/SagerNet/sing-box/releases/download/v1.12.9/sing-box-1.12.9-linux-amd64.tar.gz 
sudo tar xvzf sing-box-1.12.9-linux-amd64.tar.gz -C /opt/sing-box/
sudo cp /opt/sing-box/sing-box-1.12.9-linux-amd64/sing-box /opt/sing-box/sing-box

# 客户端：安装到用户目录 ~/.proxy/
mkdir -p ~/.proxy/conf
wget https://github.com/SagerNet/sing-box/releases/download/v1.12.9/sing-box-1.12.9-linux-amd64.tar.gz 
tar xvzf sing-box-1.12.9-linux-amd64.tar.gz -C ~/.proxy/
cp ~/.proxy/sing-box-1.12.9-linux-amd64/sing-box ~/.proxy/

使用 233boy 脚本生成配置时遇到了 systemd-unit 冲突，修改了 233boy 脚本中的 unit 位置为 /etc/（/etc/sing-box/sh/src/systemd.sh）

原理：代理协议 × 传输方式 × 传输安全

其实可以把处理需要代理的数据分成三个部分:

  1. 最上层的第一个部分就是我们熟知的各种代理协议，比如 ss、vmess、vless、trojan、socks、anytls 等等
  2. 第二部分是传输方式，也就是上层经过代理协议处理的数据用什么方式传输，比如 raw 原始状态、ws、kcp、grpc、xhttp、httpupgrade、meek 等等 我们熟悉的 vmess+ws，就是将上层 vmess 处理后的数据通过 ws 传输，这层一般不对数据进行加密，要么是在第一层就通过代理协议加密了，要么是交给第三层的传输安全来处理
  3. 最底层也就是我们熟知的 tls 以及 reality

通过这个图我们就可以实现任意协议组合任意传输，比如我可以搭建普通的 vmess 节点，也可以搭建 ss+ws 的节点，或者 ss+grpc+reality 还可以将原本的协议组合打乱，比如 trojan 协议默认情况下就是套了 tls，我们可以给她换成 reality 或者直接脱掉 tls 让她裸奔 anytls 也是类似，协议默认设计成了套 tls，但我们可以给他套上 reality，也就变成了 anyreality 了

Reality 客户端 uTLS 指纹：必须配置（2026-08 实测）

  • Reality 客户端强制要求 uTLS 指纹：删除 utls 块或 "enabled": false 时配置直接无法启动，sing-box check 报错 FATAL initialize outbound[0]: uTLS is required by reality client（v1.12.x 实测），比「断连」更严格——连进程都起不来
  • 指纹不限于 chrome：换 firefox 等任意 uTLS 指纹均正常（实测可达 200），chrome 只是最通用的选择
  • Cloudflare 场景澄清：
    • 目的站挂在 Cloudflare CDN 后面时，Cloudflare 会做 TLS 指纹识别（JA3/JA4），非浏览器指纹（Go 原生 TLS）的连接会被拦截/重置——这才是配置 chrome 指纹的现实意义
    • 若「cloudflare dns」指用 1.1.1.1 做 DNS 服务器（UDP 53），与 TLS 指纹完全无关，不会因此断连

套 Cloudflare CDN 时的传输层选择（2026-08 实测/查证）

把服务端放到 Cloudflare CDN 后面时（隐藏 VPS IP / 优选 IP），传输层兼容性如下：

传输过 CF说明
ws✅CF 官方支持（WebSocket）
grpc✅CF 官方支持（面板需开 gRPC 开关）
httpupgrade✅与 ws 同属 HTTP Upgrade 机制，CF 透传 101，实测可用
http（HTTP/1.1 CONNECT）❌CONNECT 方法 CF 不透传
h2（HTTP/2 extended CONNECT）❌xray 旧版 h2 传输依赖的 RFC 8441 extended CONNECT，CF 无此特殊回源支持

要点：

  • sing-box 没有独立的 "h2" 传输类型（1.12.x 实测 unknown transport type: h2），"vless+h2+tls" 是 xray 旧版术语；sing-box 的 HTTP 族传输是 http / httpupgrade / ws / grpc
  • CF 只对 WS、gRPC 有特殊回源支持，其它 HTTP 流量按普通网页处理，因此基于 CONNECT 的传输（http / h2）无法承载代理数据流
  • Reality 不能过 CF：TLS 在 CF 边缘终结，客户端拿到的是 CF 证书，Reality 镜像握手机制失效；套 CF 需自有域名 + CF 托管证书，传输层配普通 TLS

systemd 服务化

服务端（系统级，可加载 conf 目录合并配置）

sudo loginctl enable-linger user
sudo loginctl show-user user

如果您希望为所有用户启用 linger，可以编辑 /etc/systemd/logind.conf 文件，并将 LingerDefault 选项设置为 yes，然后重启 systemd-logind

sudo mkdir -p /opt/sing-box/conf
cat <<EOF | sudo tee /etc/systemd/system/sing-box-manual.service
[Unit]
Description=sing-box Service
Documentation=https://sing-box.sagernet.org/
After=network.target nss-lookup.target
[Service]
User=user
ExecStart=/opt/sing-box/sing-box run -c /opt/sing-box/config.json -C /opt/sing-box/conf
Restart=on-failure
RestartPreventExitStatus=23
RestartSec=10s
LimitNPROC=10000
LimitNOFILE=1048576
PrivateTmp=true
ProtectSystem=full
#CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_BIND_SERVICE
#AmbientCapabilities=CAP_NET_ADMIN CAP_NET_BIND_SERVICE
[Install]
WantedBy=multi-user.target
EOF

后续需要添加新的 outbounds 可以直接添加在 /opt/sing-box/conf/ 中，sing-box 会自动 merge；主配置在 config.json 中

客户端（用户级 systemd）

mkdir -p ~/.proxy/conf
cat <<EOF > ~/.config/systemd/user/sing-box-manual.service
[Unit]
Description=sing-box Service
Documentation=https://sing-box.sagernet.org/
After=network.target nss-lookup.target
[Service]
ExecStart=/home/user/.proxy/sing-box run -c /home/user/.proxy/config.json -C /home/user/.proxy/conf
Restart=on-failure
RestartSec=10s
[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user start sing-box-manual.service
systemctl --user show-environment
journalctl --user -ex -u sing-box-manual.service
