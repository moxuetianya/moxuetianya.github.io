高效CC++调试

关注我的朋友可能会发现，我一开始分享的内容大部分是关于C++的。这是因为我一开始毕业工作的时候，做的是C++后端开发工作。在这个过程中积累了许多经验，也向很多优秀的人身上学习。

我之前写过的文章或者回答，下面是赞比较多的（一千赞到一两百赞）。这些是我个人的实际经验和思考（站在巨人的肩膀上）。

  • CrackingOysters：你还在用GDB调试程序吗？
  • CrackingOysters：什么是move？理解C++ Value categories，move， move in Rust
  • CrackingOysters：两大绝招debug core dump？
  • CrackingOysters：如何阅读简单的汇编（持续更新)
  • CrackingOysters：The Coroutine in C++ 20 协程初探
  • CrackingOysters：RAII:如何编写没有内存泄漏的代码 with C++

当清华大学出版社的编辑联系我有没有兴趣写书的时候。我知道自己距离写书还有一定的距离。但是我想到了之前在美国带我的大牛和他的高效调试的书稿。于是我联系他，想在他书稿之上我添加一些内容，合作出一本书。他欣然同意了！（他的书稿之前我在这里提到过 CrackingOysters：Effective Debugging 引言。）

经过我们的努力，《高效C/C++调试》出版了！本书旨在探讨系统性调试的方法论和思维方式，主要聚焦于C/C++。但是大部分原理是与具体语言无关。最近我主要写NodeJS大语言模型应用和Python算法，但是我在调试这些程序的时候，还是用到了调试符号和远程调试的思维方式。
