gcc -Wl,-Bstatic / -Bdynamic 混合链接

gcc 通过 -Wl 向链接器 ld 传参：-Bstatic 强制其后的库按静态链接，-Bdynamic 强制按动态链接。部分静态、部分动态链接的写法：

# 静态链接 libA.a，同时动态链接 libB.so
gcc ... -Wl,-Bstatic -lA -Wl,-Bdynamic -lB ...

规则要点：

  • 链接方式标记影响其后所有的 -l 库，直到出现下一个标记为止。例如 ... -Wl,-Bstatic -lA -Wl,-Bdynamic -lB ... -lC 中，libC 没有跟随标记，将按默认方式（动态）链接；
  • 前提是 -L 搜索路径中能找到对应版本的库；
  • 不指定任何标记时，gcc 默认优先动态链接：若同时存在 libc.so 与 libc.a，会链接 .so。

截图与英文原文讨论见 Telling gcc directly to link a library statically。

C++ 六种 memory_order 内存序

C++11 <atomic> 中 memory_order 枚举的六个值及定义规则：

枚举值定义规则
memory_order_relaxed不对执行顺序做任何保证
memory_order_consume本线程中，所有后续的有关本原子类型的操作，必须在本条原子操作完成之后执行
memory_order_acquire本线程中，所有后续的读操作必须在本条原子操作完成后执行
memory_order_release本线程中，所有之前的写操作完成后才能执行本条原子操作
memory_order_acq_rel同时包含 memory_order_acquire 和 memory_order_release 标记
memory_order_seq_cst全部存取都按顺序执行

要点：acquire/release 是最常用、最重要的组合，理解它们后其余内存序才好理解；consume 在实践中普遍被实现为 acquire（C++17 起建议暂时弃用）；需要全局顺序一致时用 seq_cst。

延伸阅读：线程安全、原子变量、内存顺序、内存顺序 Memory Order。

x86-64 通用寄存器与 Caller/Callee Save

x86-64 共 16 个 64 位通用寄存器，用途与保存责任（System V AMD64 ABI）：

寄存器Callee Save用途
%rax返回值寄存器；idiv/imul 也使用
%rbxyes通用寄存器
%rcx第 4 参数寄存器
%rdx第 3 参数寄存器；idiv/imul 也使用
%rspyes栈指针
%rbpyes帧指针
%rsi第 2 参数寄存器
%rdi第 1 参数寄存器
%r8第 5 参数寄存器
%r9第 6 参数寄存器
%r10通用寄存器
%r11通用寄存器
%r12~%r15yes通用寄存器

要点：

  • %rax 存函数返回值；imul 两个 64 位相乘最多产生 128 位结果，需要 %rax 与 %rdx 共同存储，idiv 的 128 位被除数同理；
  • %rsp 指向栈顶，push/pop 通过改变 %rsp 实现进栈出栈；%rbp 标识当前栈帧起始位置；
  • %rdi、%rsi、%rdx、%rcx、%r8、%r9 依次传递前 6 个整型参数；
  • Caller Save 与 Callee Save 的区别：标记为 Caller Save 的寄存器，调用方在发起调用前负责压栈保存；标记为 Callee Save 的寄存器，被调用方若要覆盖，必须先保存、返回前恢复，调用方可放心跨调用持有其值。

三种多态与 Ad-hoc 多态

《Rust 编程之道》提到三种多态形式：

  • 参数化多态（Parametric polymorphism）：同一代码作用于任意类型，行为一致，对应 Rust 的泛型；
  • Ad-hoc 多态（Ad-hoc polymorphism）：同一函数名针对不同类型有不同实现，按调用时的类型选择，对应 Rust 的 trait（及 C++ 的重载/特化）；
  • 子类型多态（Subtype polymorphism）：子类型实例可用于任何需要父类型的位置，对应 trait 对象（dyn Trait）/继承体系。

"Ad hoc" 是拉丁语常用短语，意为"特设的、特定目的的、即席的、临时的、将就的、专案的"，形容为某个特定问题、任务而专门设定的东西。中文直译"特设多态"很少见，书籍多保留原文，因此这个概念初见时容易困惑。

相关讨论见泛型特化 Specialization（特化即 Ad-hoc 多态范畴内的按类型定制）。
